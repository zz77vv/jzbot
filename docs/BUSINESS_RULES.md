# 业务不变量与回归清单

- 0.1U = 内部整数 1；余额/金额在 SQLite 以十进制文本保存，Python int 运算。
- 与旧版相同：正负号+整数+最多一位小数；零金额、非法/溢出格式静默忽略。
- 普通记账仅有效 Business 连接 owner 本人新消息，私聊、非机器人代发；编辑不改账。
- owner + customer + source_message_id 去重。不同 owner/客户不串账。失败回滚整个事务。
- 入金 `+15｜余15U`、出金 `-3｜余12U`、负数 `-20｜余-8U`、清账 `余额已清零`。
- 回执引用原指令；普通记账置顶。清账仅原余额非零才有 clear 流水/统计次数/置顶；
  原余额为零或无账本只处理消息与回执，不造空钱包/历史。历史 clear 文案仍“账本已清空”。
- `/` 保留普通纯文本最近五条、时间、历史余额及当前余额，不引入后台富消息。
- 管理员归零五分钟确认、最多十六个内存能力；取消不写库，重启后确认自然失效。
  余额、普通/管理流水水位或次数变化使旧确认失效。相同 operation_id 不能重复执行。
- 管理员归零真实应用时清零余额并保留累计收支；本已为零为 noop；完整审计和独立
  clear 来源保留，不伪造消息 ID，不创建客户回执、不置顶。
- 内部停用保留金额和统计，不意味着 Telegram 封禁，也不禁止 owner 后续正常记账。
- 正余额按余额降序，欠款按绝对值降序，全部客户按最近更新。历史入金是独立列表，
  包含曾入金而现已为零/欠款的客户。客户列表/搜索/流水每页最多十项。
- 搜索支持姓名、组合、username/@username、ID 与部分匹配；单 @、空白、超过64字拒绝。
- 历史分页在 SQL ORDER BY/LIMIT/OFFSET；读取每笔 balance_after，包含两种 clear 来源。
- 定位只静默发一个点；刷新连接、owner、enabled、can_reply；网络错误不永久 disable。
- 回执失败不重入账；10/30/120/300秒退避，RetryAfter 至少按服务端冷却等待。
- 异常提醒：pending 且失败至少3次或已创建至少15分钟；正常新 pending 不当作故障。
- 安全恢复只核验/确认连接变化，保留状态/时间/次数/原文，不立即重发或假标成功。
- 发送结果不确定时不能保证 Telegram 端恰好一次；保留 pending 并明确重复风险。

测试矩阵：移植的真实业务回归 + 直接 V2 服务/处理器/数据库测试 + 合成旧库演练 +
独立发布器安全测试。临时数据库、Mock Telegram；不得以生产客户做破坏性测试。
