# 运维与恢复

日志格式化阶段对真实配置 Token 和 token 模式脱敏，包括异常堆栈中的 API URL。
Outbox 最近错误只对管理员展示保守分类，不显示原始 URL。日志中可有排障所需 owner/
customer 数字标识，不记录客户原始消息正文。数据库 last_error 同样脱敏后截断。

待交付页展示所有 pending，异常入口只展示达到提醒门槛的任务。检查/恢复需要确认，
只在当前 owner、任务仍 pending、原连接和失败次数未变化、连接权限仍有效时修改连接。
取消/重复/过期/任务已完成均不重新发送。连接检查本身可能更新连接 enabled 状态，
但绝不触碰余额、流水和统计。不能把 Timeout 推断成客户一定收不到。

停止时先向已核验的准确 PID 发 SIGTERM，等待退出与锁释放。若停止超时，停止自动流程，
不能启动第二个实例，不能删 .jzbot.instance.lock。不要用 pkill/killall 影响其他机器人。

若发布成功但生产未成功，两种状态分别报告；不要将 GitHub SHA 当作上线证明。
若生产成功后 GitHub 访问临时失败，不停止已验收正常的生产服务。

受保护回滚点只用于本次受控切换。旧版代码留在原目录，可在 DB 兼容性核验后切回。
恢复旧版优先继续使用当前数据库，不覆盖切换后新账。需要灾难恢复时先暂停并逐客户核对，
明确恢复点后的新增账务，未经验证不能用旧副本覆盖。禁止自动定期备份或自动清理历史备份。
